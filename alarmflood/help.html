1. 这是什么

企业 IT 系统一次故障会在几分钟内触发成百上千条告警（告警洪水）， 值班工程师平均需要 40 分钟以上人工梳理才能定位根因。

本值班台把「告警流 → 根因 → 处置」这条人工链路自动化，帮值班工程师在 30 秒内回答三个问题：发生了什么 → 谁是根因 → 接下来怎么办。

3. 三种使用方式

方式一：内置演示数据集

左侧「① 数据源」选「内置演示数据集」——只读已跑好的分析产物，不需要任何配置与密钥。 数据为公开的银行微服务数据集（AIOps 挑战赛），原始告警 101,478 条， 经重复抑制与常驻搁置后剩 14,806 条（-85.4%），检出 895 个洪水窗口。 大模型列默认展示离线已跑好的产物。

方式二：导入新告警流

选「导入新告警流」，上传 csv / json / jsonl / parquet 格式的告警文件， 不用改文件格式——上传后在页面里点选哪一列是时间/实体/内容即可，详见第 9 节。

方式三：现场启用路线 B（填自己的 API Key）

左侧「③ 路线 B · 大模型接入」填入 API Key + 接口地址 + 模型名 （内置 OpenAI / DeepSeek / 通义千问 / 智谱 GLM / Moonshot / 本地 Ollama 预设，选预设自动填地址和模型）， 即可对任意窗口（含导入的数据）现场调用大模型跑根因推理与处置单生成。 「🔌 测试连接」会用一条最短请求验证 key / 接口 / 模型是否真的能通。 不填密钥时看板照常使用，详见第 6、7 节。

4. 三级分诊与瀑布图

窗口内的告警按出现规律分为三级，这是整套系统的判别基础：

层级含义在根因分析中的地位
新发 novel故障前后才出现的告警主要证据——根因大概率在发出新发告警的实体里
半常驻 semi周期性出现的背景告警辅助证据
常驻 core全天候反复响的告警已搁置，不作为根因证据

瀑布图（模板 × 时间）中：红色 = 新发信号，橙色 = 半常驻，灰色 = 常驻噪声； 横轴为窗口内时间偏移，条形越长表示该模板告警越多。

5. 路线 A：规则排序（确定性，可审计）

不依赖任何模型，四路加权打分，结果完全可复现：

信号权重含义
新发告警数0.5主证据：该实体在窗口内有多少条「新发」告警
新发越早越可疑0.15根因通常最先报警
分层加权频次0.2新发计 2.0、半常驻 1.0、常驻 0.5
分钟共现0.15与窗口内其他实体同分钟出现的程度

6. 路线 B：大模型根因推理

同一批告警证据交给大模型排序，与路线 A 互相印证：两路结论一致即可高置信派单， 分歧则触发人工复核（页面会自动给出提示）。

离线产物 vs 实时调用

  • 离线产物：由离线管线批量生成（results/llm_rankings.json）， 不花钱、开箱即看，但只覆盖内置数据集的故障窗口；
  • 实时调用：填入自己的 key 后点「▶ 现场调用大模型分析本窗口」， 任何窗口（包括你导入的数据）都能跑，会显示模型名、耗时、token 用量。
实时调用与离线管线用的是同一份 prompt，因此实时结果可以和离线产物直接对照； 实时结果按「模型 + 内容」缓存在 results/llm_cache_live/，重选窗口不重复计费， 换模型必然重算，不会串味。

幻觉防护（如实披露）

  • 模型返回的实体若不在窗口证据内，一律过滤；
  • 若候选全部是幻觉，界面会明确标注「已按规则排序兜底——这一列不属于大模型成绩」，不冒充；
  • 处置单同理：实体校验不通过就走降级模板，并标注「未采用其原始结论」。

7. 处置单与派单

根因确认后系统生成结构化处置单（摘要 / 根因判定 / 处置建议 / 已归并告警）， 值班工程师据此操作。处置单可以导出 JSON。

派单：两步走（人在回路）

找到根因后，值班员原本要手工做三件事：查「这个服务归谁管」、按格式写工单、 发到对应值班群。派单把这三步合成一次点击——系统查责任团队映射表 （config/teams.csv）自动填好工单，值班人确认内容无误后才发出（AI 只起草，不擅自执行）。

  • 「📝 生成工单预览」：填好标题 / 责任团队 / 优先级；实体未登记团队时显示「待指定」，需人工指定；
  • 优先级规则：有新发告警且置信度 ≥ 0.7 → P1，有新发告警 → P2，否则 P3；
  • 「✅ 值班人确认，发送工单」：确认后才发出。演示环境未接真实 ITSM， 正式部署时此处调用企业工单系统 webhook。

8. 批量导出工单（全部窗口）

单个窗口派单之外，值班交接与故障复盘常常要一次交出一批结论： 全部检出窗口的根因、责任团队、优先级一次性打成一张表—— CSV 可直接贴进工单系统/表格（UTF-8 BOM，Excel 打开中文不乱码），JSON 供下游系统对接。

  • 导出范围：全部检出窗口 / 仅已有正式处置单的窗口 （正式处置单由离线管线含大模型+幻觉校验生成，其余窗口用确定性规则路线给根因候选）；
  • 最少告警条数：一条告警就下根因结论没有说服力，默认过滤掉 <3 条的窗口；
  • 证据强度：≥10 条且有新发告警 = 强，≥5 条 = 中，否则 = 弱（建议优先复核）；
  • 无新发告警的窗口置信度一栏如实写「—」，不编造百分比；
  • 导出即「待确认」状态：值班人核对后再逐条发送，AI 不擅自派发。

9. 导入自己的告警流

支持格式与列映射

支持 csv / json / jsonl / parquet。不需要把文件改成任何固定格式：系统按常见列名先猜一次 （时间 / 实体 / 内容三类必填；规则ID、级别可选，给了会更准），你只需对照第 0 行样例值 在下拉框里核对、猜错了改一下。映射只存在本次会话内存里，不会改动你的原始文件。

时间列支持：2026-10-19 10:00:01 / 2026/10/19 10:00 / ISO8601 / 秒级或毫秒级时间戳（自动判别）。解析不出来的行会直接报错，而不是画出错误的时间轴。

没有实体列？从告警内容里抽

很多告警系统只有一列文本（如「主机 web01 CPU 使用率 95%」）。实体列下拉框选 「⟳ 从告警内容中抽取」，系统按三级策略自动抽：

  1. 正则链：IP → 键值对（host=node-7）→ 中文前缀（主机 web01）→ 域名 → 带编号名（Redis02）→ 连字符名（svc-a）；
  2. 模板内差分：同一模板下「同一位置变化的非数字词」即实体（svc-a / svc-b）；
  3. 模板间差分：一族只差一个词的模板（节点A / 节点B），差异位即实体；
  4. 仍抽不出 → 如实记 (未识别)，不参与根因归属——一个笼统的「未识别」不算证据。

处理完成后有「实体抽取结果核对」面板：覆盖率、各方法命中条数、Top 实体、 内容→实体→方法样例。抽得不准可填自定义正则（取第 1 个捕获组）点「重新抽取」，不用重传文件。

10. 数据来源与隐私

模式数据隐私
内置演示AIOps 挑战赛公开数据集（银行系统）界面只读本地分析产物，不上传
导入模式你上传的告警文件仅在本机内存处理，不落盘、不上传
路线 B 实时调用窗口内的去重告警证据请求只发往你自己填的接口地址
🔑 密钥安全：API Key 只存在浏览器会话内存里——不写盘、不上传、不进日志， 不随任何产物落盘，刷新页面即失效。实时调用的缓存只保存模型输出的结论， 不保存密钥。
